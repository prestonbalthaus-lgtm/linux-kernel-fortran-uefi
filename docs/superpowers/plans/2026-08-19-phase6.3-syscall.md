# Roadmap 6.3: the syscall ABI trap

What this box is, precisely: an instruction that lands in Fortran. It does not
implement a system call -- `sys_read`, `sys_write` and `sys_exit` are scaffolds
that record what they were asked -- and it does not drop to Ring 3, which is
7.1. What it establishes is the PATH, and the path is the part that is hard to
get right once.

## The five decisions

### 1. IRETQ, not SYSRETQ

SYSRET derives CS from `STAR[63:48] + 16` and SS from `+ 8`, both with RPL
hardwired to 3 (`segment.h:177-186`). There is no encoding of it that returns
to CPL 0, so it cannot return the only caller 6.3 has -- kernel code checking
that the trap routes. Linux has the same problem from the other side and
answers it the same way: every kernel-to-kernel return in `entry_64.S` is
IRETQ.

In 64-bit mode IRETQ ALWAYS pops SS:RSP, privilege change or not, so ONE frame
shape serves ring 0 now and ring 3 at 7.1. Only the two selectors in it change.

### 2. STAR[63:48] is zero, and a gate asserts it

A plausible-looking value there -- `__USER32_CS`, say, copied from
`common.c:2306` -- would name Ring 3 descriptors this GDT does not contain: a
register that reads as configured and faults the first time it is used. Zero is
the honest value while there is nothing to name.

That reasoning is only sound while nothing in the image executes SYSRET, so
`sysretcheck-boot` objdumps the kernel and refuses one. Roadmap 7.1 adds the
three descriptors, fills in the sysret half, and DELETES that gate -- which is
the right time for it to go and not before.

### 3. The stack switch is software's, and that is why IF is in FMASK

`entry_64.S:65-66`: "SYSCALL does not save anything on the stack and does not
change rsp." Between arriving at the stub and having a kernel stack there is a
window in which RSP is still the caller's; an interrupt taken in that window
would push its frame onto a pointer the caller chose. FMASK clears IF as part
of the instruction, so the window cannot be interrupted. That is the mechanism,
not hygiene.

NO SWAPGS, and it is a property of this kernel rather than a shortcut. Linux
swaps GS because its stack pointer lives in per-CPU memory addressed through
it; nothing in this tree uses a GS base (`boot.S:367` and `gdt_flush.S:34` load
`%gs` with a data selector and never touch its base). A swapgs here would
corrupt the base rather than switch it, and it is the first thing 7.1 revisits
if per-CPU state ever arrives.

### 4. The router reads the frame, which dissolves the R10 problem

The Linux syscall ABI puts argument 4 in R10 rather than RCX because SYSCALL
destroys RCX with the return address. A router taking its arguments in
registers would have to know that and shuffle. This one reads slots out of the
`fk_regs_t` the stub pushed, so R10 is simply the field called `r10` -- and RCX
and R11 are visibly the clobbered values they are.

`fk_regs_t` is now PUBLISHED by `fk_idt_m` rather than copied, so the exception,
interrupt and syscall paths are described by one type. The stub builds the same
22 quadwords `isr_common` and `irq_common` build; `int_no` is -1, an
unmistakable "not a vector" that needs no constant shared between the assembly
and the Fortran.

### 5. The result goes back in the frame's RAX

`POP_GPRS` is what puts it in the register, so writing the field IS returning
the value. `fk_syscall_handler` is a subroutine, not a function, for that
reason: a handler that returned its answer as a function result would compile,
run, and deliver nothing to the caller.

## Where each claim is established

| claim | where | why not the other place |
|---|---|---|
| STAR's composition, FMASK's bit set | host suite | pure values over the GDT selectors |
| the router's dispatch, including R10 | host suite | ordinary code over a frame C can build |
| `syscall_init`'s read-back notices a dropped write | host suite | only a MODEL MSR file can drop one |
| the four registers took the values | boot gate | needs a real WRMSR |
| a SYSCALL instruction arrives | boot gate | the host cannot execute one |
| FMASK cleared what it names | boot gate | needs a real caller to set the flags and a real instruction to clear them |

THE HOST SUITE MUST NOT EXECUTE WRMSR and does not: a test that programmed the
real `MSR_LSTAR` would point the HOST's system calls at a Fortran routine in a
test binary. The model that replaces it is worth more anyway, because it can be
made to REFUSE a write -- which is the only way to check the read-back at all.

THE CONSTANTS ARE ALL THE KERNEL'S. `asm/msr-index.h` and
`uapi/asm/processor-flags.h` both compile standalone out of the vendor tree, so
every MSR number, `EFER_SCE` and all fourteen FMASK flags are spelled with
Linux's own names. `FK_SYSCALL_FMASK` is diffed against the OR of that list,
not against `0x257FD5` written a second time.

AND MSR_LSTAR HAS AN INDEPENDENT CHANNEL: the sentinel reads `fk_syscall_entry`
out of `kernel.elf`'s symbol table and diffs it against what the guest read back
out of the register. The guest never sees that number.

## Two defects found in the first draft

**The stub read `%ss` and `%cs` through `%rax`**, which is where the caller puts
the SYSTEM CALL NUMBER. Every call would have dispatched on a segment selector.
The slots are reserved and written 16 bits wide instead, touching no
general-purpose register -- every one of them still holds an argument.

**The state block described a moment, not the end of the sequence.** Words 6-8
were snapshotted straight after the first call and left, so it published "last
number 1" after three calls had been made. The gate caught it, which is the
answer to why the gate publishes a sequence rather than a verdict.

## What FMASK's assertion does not reach

The boot check sets IF and the arithmetic flags before the instruction and
requires none of them to survive. It does NOT set TF, DF, IOPL, NT or RF, and
that is deliberate: TF would single-step the instruction before the syscall, RF
cannot be set by POPFQ at all, and a kernel running with DF set even briefly
would break every string operation between there and the instruction. Those
five are covered by the value check on FMASK itself and by the sentinel's
independent flag list, and are named here as what the live assertion does not
prove.
